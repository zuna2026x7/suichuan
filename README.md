# 随传（Suichuan）

把一台安卓手机上**已安装的应用、普通文件、一段文字**，通过网络传到另一台安卓手机上；对方还没装随传时，也能**面对面扫码**把随传本身装过去。

不用像快牙、互传那样折腾 Wi-Fi / 热点配对；也不用像 QQ/微信传文件那样，收到之后还要去文件管理器里把 `xxx.apk.1` 改名才能装——随传分享的是**取件码和文字**，不是文件，接收方在 App 内部下载、点一颗「安装」按钮就完事，全程不接触文件。

最新版本见 [Releases](https://github.com/zuna2026x7/suichuan/releases)。最初的设计思路和取舍见 [DESIGN.md](DESIGN.md)。

## 功能

- **发送应用**：列出手机上已安装的用户应用，点一个即可。普通应用原样打包；由多个部分组成的应用（Split）会自动打成一个完整的包，不会出现「缺组件装不上」。
- **发送文件**：从系统文件选择器选一个普通文件（文档、图片、视频、压缩包等）。接收方下载后保存到「下载」文件夹，并可按类型打开；文件类型显示为「PDF 文档」「图片」这类中文名称。经发送文件收到的 `.apk` 只保存不安装——想装应用请走「发送应用」。
- **发送文字**：写或粘贴一段文字（上限 64KB），生成取件码，接收方直接看文字。
- **取件码**：发送完成页显示分组的 6 位取件码（如 `123 456`）、二维码、一键复制、具体截止时间（72 小时内有效），并可把整段文字发到微信/QQ。
- **两种中转方式**：
  - **取件服务**（默认）：自建的 Node 后端（见 [server/](server/README.md)），单个文件上限 100MB；
  - **临时托管**：超过 100MB 的应用或文件自动改走 Litterbox（72 小时过期），总上限 1GB；取件服务出错时发送页也会给出「改用临时托管发送」。
  - 上传时如果是手机流量，会先提醒大小并确认；上传和下载都可以随时**取消**，取消会真正中断网络传输。
- **三种接收方式**：输入取件码（带空格也能识别）、扫码接收、或直接粘贴对方分享的整段文字 / 下载链接。
- **接收即安装**：收到应用时，在 App 内部下载（显示已下载多少 / 总大小，可取消）、做完整性校验（SHA-256）、显示应用名/版本/大小确认卡片，点「安装」走系统安装流程（分片包用 PackageInstaller 一次装好）。安装结果直接显示在页面上：成功可「打开应用」，失败会翻译成人话（缺组件、签名冲突、不能降级、空间不足、包损坏…）并可「重新安装」。
- **救援入口**：已经躺在 QQ/微信里那个打不开的安装包，在 QQ/微信里「用其他应用打开」选随传、或在随传里直接选它——只看内容不看名字，确认是安装包就直接装，不用改名。
- **面对面分享随传**：首页「推荐给朋友」。手机上开一个只在局域网可见的小下载服务并显示二维码，对方连同一个 Wi‑Fi 或你的热点，用系统相机或浏览器扫码就能下载随传本身，不走公网、不耗流量。链接带随机字符，离开页面或 10 分钟没人下载自动关闭；用微信/QQ 扫码会提示「在浏览器打开」（它们会拦截安装包下载）。
- **检查更新**：见下一节。
- **出问题时**：首页和失败页都有「上传日志帮我看看」，把脱敏后的日志传到取件服务。

## 检查更新 / 发布新版本

- **App 内**：首页底部「检查更新（当前 vX）」手动检查；每天打开时还会静默检查一次，有新版只在首页顶部出现「发现新版本」按钮，不弹窗、失败不打扰。检查页显示更新内容 → 下载（私有缓存，校验 SHA-256）→ 交给系统安装器，安装结果常驻显示。可「跳过这个版本」。
- **数据来源**：本仓库 GitHub Releases 的「最新正式版」（`/releases/latest`，草稿和预发布不算）里第一个 `.apk` 附件。版本按 tag（`v1.4`）和 App 的 versionName 逐段比较。
- **发版**：在 master 上推一个 tag（`git tag v1.5 && git push origin v1.5`）→ `Release APK` 工作流跑单元测试、用固定发布密钥签名、按 tag 写入版本号（`v1.5` → versionName `1.5` / versionCode `10500`），并核对签名指纹，生成**草稿** Release → 在 GitHub 上检查后点「Publish release」，用户才会收到更新。
- **签名密钥**：加密后放在 `signing/release.jks.enc`（AES-256），解密密码存在仓库 Actions Secret `KEY_PASS`（也认 `KEYPASS` / `SUICHUAN_KEYSTORE_PASSWORD`），别名 `suichuan`。**密码务必另外保存好**：丢了就再也发不了能覆盖安装的更新。也可以不用仓库里的密钥，改设 `SUICHUAN_KEYSTORE_BASE64 / SUICHUAN_KEY_ALIAS / SUICHUAN_KEY_PASSWORD`。
- **从旧版升级**：v1.3 及以前的安装包每次都是不同的临时 debug 签名，没法覆盖升级；从 v1.4 起用固定密钥签名，旧版用户需要**先卸载一次**再装 v1.4，之后就能在 App 里直接更新。签名不同时，检查页会说明要先卸载旧版。

## 构建（GitHub Actions）

本仓库用 GitHub Actions 云端构建，不需要在本地装任何安卓环境：

- **Android** 工作流（每次推送）：JDK 17 + Gradle 8.7，先跑单元测试（`testDebugUnitTest`），再打 debug 包（`assembleDebug`）。在运行页面下方的 **Artifacts** 里下载 `suichuan-debug-apk` 即可测试。debug 包每次签名都不同，只用于测试，不能覆盖正式版。
- **Release APK** 工作流（推 `v*` tag 时）：见上一节。
- **Verify backend** 工作流（手动）：从 GitHub Runner 检查线上取件服务是否可达，只读 + 一条 60 秒自动过期的文字记录，不改服务器。

单元测试覆盖纯逻辑：传输内容编解码、安装错误翻译、安装包内容识别、版本比较、中文错误文案 / 文件类型 / 取件码分组、局域网分享服务器（下载页、整包与断点下载、错误令牌 404、局域网地址选择）。

## 在 Windows 上用 Android Studio 打开

1. 安装 Android Studio（自带 JDK 和 SDK），SDK 装 API 34；
2. 用 Android Studio 打开本仓库根目录，等 Gradle 同步完成；
3. 项目里带了 Gradle Wrapper（`gradlew.bat`），也可以直接在根目录命令行运行 `gradlew.bat testDebugUnitTest assembleDebug`；
4. 点运行按钮装到手机上调试，或到 `app/build/outputs/apk/debug/` 取 APK。

技术基线：Kotlin，原生 Views + Material Components（无 Compose），minSdk 26，target/compileSdk 34，AGP 8.5.2，Kotlin 2.0.20，Gradle 8.7。依赖只有 AppCompat、Material、OkHttp、ZXing（含 zxing-android-embedded 扫码）和 JUnit；局域网分享用系统自带 Socket，不引入额外库。

## 取件服务（server/，Node.js）

取件码、文件中转和日志上传由 `server/` 里的 Node 服务提供（纯标准库，无 npm 依赖，Node 18+）。部署、配置和测试见 [server/README.md](server/README.md)。

- App 连接的地址写在根目录 `gradle.properties` 的 `transferApiBase`（当前为 `http://198.200.49.120:8081`），改完重新构建即可；留空则只能走临时托管。
- 取件码记录和文件最长保存 72 小时，到期自动清理；单个文件上限 100MB（`SUICHUAN_MAX_BYTES`），文字上限 64KB。
- 目前是明文 HTTP（App 开启了 `usesCleartextTraffic`），后续计划换 HTTPS。

早期版本用过 Cloudflare Worker + KV，v0.6 起已经下线并删除，改为这个 Node 服务。

## 两台手机全流程测试清单

准备：两台安卓手机（A 发送、B 接收），都装上随传，网络任意（可以不在同一个 Wi-Fi，甚至一台用流量）。

- [ ] A：首页 →「发送应用」→ 选一个小一点的普通应用 → 看到上传进度走完；中途点「取消」能立即停止；
- [ ] A：发送完成页出现分组的 6 位取件码、二维码、截止时间，「复制」可用；
- [ ] A：点「发给微信/QQ 好友」，把整段文字发给 B 的微信/QQ；
- [ ] B：复制整段文字 → 打开随传 → 接收页 → 粘贴 →「开始接收」→ 看到下载进度 → 出现确认卡片（应用名、版本、大小对得上）；
- [ ] B：点「安装」→ 第一次会让允许随传安装应用，去设置里开一次 → 回来再点安装 → 系统弹窗点「安装」→ 页面显示安装成功，「打开应用」可用；
- [ ] B：只输 6 位码（带不带空格都试一下），能收到同一个应用；
- [ ] A：发一个超过 100MB 的应用，应自动改走临时托管，B 照样能收到；
- [ ] A：选一个由多个部分组成的大应用（列表里会标注「会完整打包」）发送，B 能装上并打开，不报「缺少组件」；
- [ ] 文件：A 发一个 PDF，B 收到后「保存到下载」并能打开；Android 8–9 手机上会先请求存储权限；
- [ ] 救援：用 QQ 把任意一个安装包发给 B，确认 B 收到的是改过名的文件（打不开）→ 在 QQ 里点它 →「用其他应用打开」→ 选随传 → 点安装，能装上；
- [ ] 流量提醒：A 关掉 Wi-Fi 只用流量发送，发送前应弹出「大约要用 XX MB 流量」的确认；
- [ ] 失败文案：B 上先装一个应用商店版本的应用，再用随传接收同一应用的另一个来源版本，安装失败时应显示中文说明（来源不同要先卸载）和「重新安装」；
- [ ] 面对面分享：A 首页「面对面分享随传」→ B 连同一 Wi‑Fi（或 A 的热点）用相机扫码 → 浏览器下载安装成功；A 页面显示「已被下载 1 次」；
- [ ] 检查更新：首页「检查更新」能显示当前版本和最新版本。

## 局限（先说清楚）

- **只传安装包，不传数据**：账号、聊天记录、存档都不会过去，和市面上所有同类工具一样。
- **银行、支付、带完整性校验的应用**：装得上也可能打不开或不能用（设备绑定、Play Integrity 等），这是应用自己的限制。
- **文件会过期**：取件服务和 Litterbox 里的文件都只存 72 小时；对方没及时接收就要重新发送。超过 1GB 的应用或文件发不了。
- **流量是你自己的**：上传和下载都走各自手机的网络（面对面分享除外）；发送前 App 会报大小，接收前也会显示大小。
- **面对面分享**：需要两台手机在同一局域网；商场、酒店等公共 Wi‑Fi 常常禁止设备互访，这时请开热点。分享期间要停留在分享页面。
- **转屏会保留进度**，但如果 App 在后台被系统杀掉，正在进行的传输需要重新开始。
- 没有账号、没有历史记录同步。已在 Play 商店受 DRM 保护的付费应用，即使传过去也可能无法运行；请只分享你有权利分享的应用。
