# 随传（Suichuan）

把一台安卓手机上**已安装的应用**，通过网络传到另一台安卓手机上安装。

不用像快牙、互传那样折腾 Wi-Fi / 热点配对；也不用像 QQ/微信传文件那样，收到之后还要去文件管理器里把 `xxx.apk.1` 改名才能装——随传分享的是**取件码和文字**，不是文件，接收方在 App 内部下载、点一颗「安装」按钮就完事，全程不接触文件。

设计背景和取舍见 [DESIGN.md](DESIGN.md)。

## 功能

- **发送应用**：列出手机上已安装的用户应用，点一个即可。普通应用原样打包；由多个部分组成的应用（Split）会自动打成一个完整的包，不会出现「缺组件装不上」。
- **云端中转**：安装包上传到 Litterbox 临时存放（72 小时自动过期），上传时如果是手机流量会先提醒大小并确认。文件不经过任何自有服务器。
- **三种接收方式**：
  1. 6 位**取件码**（需要部署下面的取件码服务 Worker）；
  2. **二维码 / 分享文字**：不需要任何服务，发送完成页生成二维码，并能一键把整段文字发到微信/QQ，对方粘贴到随传里即可接收；
  3. 直接粘贴**下载链接**。
- **接收即安装**：在 App 内部下载、做完整性校验（SHA-256）、显示应用名/版本/大小确认卡片，点「安装」走系统安装流程（分片包用 PackageInstaller 一次装好）。安装失败会翻译成人话（缺组件、签名冲突、不能降级、空间不足、包损坏…）。
- **救援入口**：已经躺在 QQ/微信里那个打不开的安装包，在 QQ/微信里「用其他应用打开」选随传、或在随传里直接选它——只看内容不看名字，确认是安装包就直接装，不用改名。

## 怎么拿到能装的 APK（GitHub Actions 构建）

本仓库用 GitHub Actions 云端构建，不需要在本地装任何安卓环境：

1. 把仓库推到 GitHub（见下方说明）；
2. 打开仓库的 **Actions** 页 → 选择 **Android** 工作流；
3. 构建成功后，在那次运行页面下方的 **Artifacts** 里下载 `suichuan-debug-apk`，解压得到 debug APK，传到手机上安装即可（手机会要求允许「安装未知应用」，按提示开一次）。

工作流做的事：JDK 17 + Gradle 8.7，先跑单元测试（`testDebugUnitTest`），再打 debug 包（`assembleDebug`）。单测覆盖三块纯逻辑：传输内容的编解码、安装错误翻译、安装包内容识别。

## 在 Windows 上用 Android Studio 打开

1. 安装 Android Studio（自带 JDK 和 SDK），SDK 装 API 34；
2. 用 Android Studio 打开本仓库根目录，等 Gradle 同步完成；
3. 项目里带了 Gradle Wrapper（`gradlew.bat`），也可以直接在根目录命令行运行 `gradlew.bat testDebugUnitTest assembleDebug`；
4. 点运行按钮装到手机上调试，或到 `app/build/outputs/apk/debug/` 取 APK。

技术基线：Kotlin，原生 Views（无 Compose），minSdk 26，target/compileSdk 34，AGP 8.5.2，Kotlin 2.0.20，Gradle 8.7。依赖只有 AppCompat、Material、OkHttp、ZXing 和 JUnit。

## 取件码服务（可选，Cloudflare Worker）

取件码不是必须的：不部署它，二维码/分享文字照样能用。部署后发送页会多出一个 6 位取件码，对方手输就能接收。

1. 按 [worker/README.md](worker/README.md) 部署（建一个 KV、填 `wrangler.toml`、`wrangler deploy`），拿到 `https://...workers.dev` 地址；
2. 把地址填进根目录 `gradle.properties`：`transferApiBase=https://你的地址`；
3. 重新构建 App 即可。

Worker 只存元数据（取件码 → 应用名/大小/校验值/下载链接，KV 里最长存 72 小时），**文件本身仍然在 Litterbox**，不经过 Worker。

## 两台手机全流程测试清单

准备：两台安卓手机（A 发送、B 接收），都装上随传，网络任意（可以不在同一个 Wi-Fi，甚至一台用流量）。

- [ ] A：首页 →「发送应用」→ 选一个小一点的普通应用 → 看到上传进度走完；
- [ ] A：发送完成页出现二维码（部署了 Worker 的话还有 6 位取件码）；
- [ ] A：点「发给微信/QQ 好友」，把整段文字发给 B 的微信/QQ；
- [ ] B：复制整段文字 → 打开随传 →「输入取件码」→ 粘贴 →「开始接收」→ 下载完成出现确认卡片（应用名、版本、大小对得上）；
- [ ] B：点「安装」→ 第一次会让允许随传安装应用，去设置里开一次 → 回来再点安装 → 系统弹窗点「安装」→ 提示安装完成，能打开；
- [ ] （有取件码时）B：只输 6 位码，重复上面流程，能收到同一个应用；
- [ ] A：选一个由多个部分组成的大应用（比如大型游戏或从 Play 装的应用，列表里会标注「会完整打包」）发送，B 能装上并打开，不报「缺少组件」；
- [ ] 救援测试：用 QQ 把任意一个安装包发给 B，确认 B 收到的是改过名的文件（打不开）→ 在 QQ 里点它 →「用其他应用打开」→ 选随传 → 点安装，能装上；
- [ ] 流量提醒测试：A 关掉 Wi-Fi 只用流量发送，发送前应弹出「大约要用 XX MB 流量」的确认；
- [ ] 失败文案测试：B 上先装一个应用商店版本的应用，再用随传接收同一应用的另一个来源版本，安装失败时应显示中文说明（来源不同要先卸载），而不是英文错误码。

## 局限（先说清楚）

- **只传安装包，不传数据**：账号、聊天记录、存档都不会过去，和市面上所有同类工具一样。
- **银行、支付、带完整性校验的应用**：装得上也可能打不开或不能用（设备绑定、Play Integrity 等），这是应用自己的限制。
- **取件码依赖 Worker**：没部署 Worker 时没有取件码，只能用二维码/分享文字/链接；部署后取件码最长有效 72 小时。
- **文件会过期**：文件在 Litterbox 只存 72 小时；对方没及时接收就要重新发送。Litterbox 单文件上限 1GB，超大的游戏可能发不了。
- **流量是你自己的**：上传和下载都走各自手机的网络，这是本产品刻意的取舍（换来不用折腾 Wi-Fi）；发送前 App 会报大小，接收前也会显示大小。
- 这是 MVP：没有账号、没有历史记录同步、没有断点续传。已在 Play 商店受 DRM 保护的付费应用，即使传过去也可能无法运行；请只分享你有权利分享的应用。
